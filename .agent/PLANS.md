# KothaFlow execution plans

Use an ExecPlan for work spanning multiple subsystems, changing schema/contracts, adding providers/integrations, or taking more than one focused session.

An ExecPlan must let another coding agent continue without chat history.

## Required sections
### Goal
### Current state
### Scope / out of scope
### Design
Data flow, boundaries, authorization, failures, provider considerations.
### Milestones
Checkboxes with verifiable outcomes.
### Validation
Automated/manual checks including tenancy and voice evals when relevant.
### Rollout and rollback
### Decisions discovered during implementation

Update the plan while working. Do not mark milestones complete without validation. On completion, update `docs/DECISIONS.md` and `docs/PROJECT_STATE.md`.
